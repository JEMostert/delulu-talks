# Delulu Talks v0.12.2 — Faster workspace drawing

This patch addresses sluggish clicking, typing and scrolling in the native app window, especially on Linux Wayland.

- Wayland no longer forces Chromium to draw the entire window without hardware acceleration. Chromium selects the available compositor normally.
- The ocean pauses whenever a workspace or quick settings panel is open. Large workspace sheets no longer blur the background across nearly the entire window.
- When hardware compositing is unavailable, the ocean stays static and backdrop blur is disabled. The renderer follows Electron's compositing status, including later changes, instead of guessing from WebGL availability.
- For drivers that require software rendering, launch with `DELULU_SOFTWARE_RENDERING=1`. This affects window drawing only; speech inference keeps its existing device configuration.

Native Wayland checks covered navigation, Editor keyboard input and Settings scrolling in a private desktop. Short CPU samples with Models open measured approximately 7% compositor CPU in v0.12.1 and 0.7% in the changed build; the explicit software fallback measured 0.0% in a three-second idle sample. These are local observations, not latency guarantees or cross-platform benchmarks. See the [rendering review](../performance-review-v0.12.2.md) for methodology and limits.

Existing unit tests, formatting, typechecking and the production build pass. Release automation verifies platform packages and updater checksums before publication. Install the update and restart the app to use the new drawing path. No speech runtime reinstall is needed for this patch.
