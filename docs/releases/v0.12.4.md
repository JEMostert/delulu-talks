# Delulu Talks v0.12.4 — Hold to talk until release

Hold-to-talk now waits until the shortcut is released before delivering text. Previously, live typing could send Ctrl+V while the dictation shortcut was still held. This creates a potential conflict with desktop shortcut activation, including before text appears. Hold mode now avoids that conflict entirely.

Live typing remains available in **Press to toggle** mode, where you release the keys after starting the recording. Settings and the tray explain this distinction. The live typing preference is retained for use in toggle mode.

The 12-second R2T2 phrase boundary is not a recording limit. Capture remains bounded to ten minutes; silence auto-stop applies only when explicitly enabled.

Verification: 73 TypeScript tests and 19 Python tests pass, including a regression that keeps hold-mode capture active without live paste and delivers once after Stop, plus existing toggle-mode streaming tests. Both browser capture tests, formatting checks, and the production build also pass. The original local v0.12.3 profile had hold-to-talk and live typing enabled, silence auto-stop disabled, and multiple short recordings marked as live deliveries. That observation motivates the fix; it is not itself a recording of physical key state.

No runtime repair, model download or history migration is needed.
