# Worker protocol version 1

Every JSON-lines request and terminal response carries `protocolVersion: 1`. Request IDs are nonempty strings of at most 128 UTF-8 bytes, commands at most 64 bytes. The desktop generates UUIDs and validates before spawn/write; Python independently validates before dispatch. Missing or incompatible versions produce an actionable restart/repair error rather than accepting a different wire contract. Python returns a correlated request-local rejection for a valid ID; a malformed ID cannot be correlated and terminates the desktop generation. Structured progress lines retain their separate `@delulu-progress:` prefix and carry the active request ID, command, stage and bounded detail.

Request fields use their actual types without string/boolean coercion. Load commands accept an optional string cache path; Magic load accepts only the offered writing model IDs (`qwen35Medium`, `phi4Mini`). Transcription requires a nonempty audio path, an optional string language hint (`auto` requests detection where the adapter advertises it), optional string `hotwords` of at most 3,000 characters, and finite nonnegative duration. Rewriting requires string text and optional existing preset (`spoken-corrections`, `polish`, `concise`, `structured`, `prompt`, `bullet-points`, `professional-message`), string instructions and boolean inference permission. Transport text/instructions caps are 500,000/4,000 UTF-16 units; the existing 50,000-character writing backend limit still applies. Python recognizes only the allowlisted worker commands; unknown commands receive a correlated rejection.

Success responses contain a result and no error; failures contain a nonempty error of at most 8,000 UTF-8 bytes and no result. Python validates backend results before emitting, and the desktop validates both the envelope and the matching pending command result before completing it. Status results require a boolean loaded flag; transcription requires text/language and finite nonnegative duration/processing time; rewriting requires text/model, processing time, input/output character counts and inference-permission metadata. Shutdown acknowledges `shutdown: true`. Nullable status model/device values and optional inference timing remain supported. JSON rejects nonfinite numbers and more than 64 nesting levels.

The byte, queue and diagnostic limits in [worker bounds](worker-bounds.md) remain in force. Version/schema errors preserve source audio, model runtimes, settings and transcripts. This is a wire contract, not evidence of native MLX/CUDA behavior.

## Progress events

A progress line contains `{protocolVersion: 1, type: "progress", id, command, stage, detail}` and an optional finite `fraction` between zero and one. IDs match terminal response IDs; stages/commands are nonempty strings bounded to 64 UTF-8 bytes, and detail is at most 4,000 UTF-8 bytes. The desktop validates the event separately from terminal responses, then publishes it only while the matching ID and command are pending. Unknown IDs, completed work, mismatched commands and prior generations cannot update the current status. Malformed reserved-prefix events fail the generation with intentional repair/retry; ordinary library logs are never interpreted as progress.

Python scopes the operation ID/command around dispatch with a context variable that resets on exit. MLX and CUDA R2T2 download/conversion/loading emitters use that context; a direct backend call without a worker operation logs to stderr instead of inventing an ID. Existing UI callbacks retain bounded text compatibility and can also receive structured metadata. Events do not invent model percentages or expose transcript contents.
