# Runtime consolidation: implementation and remaining gates

This pass integrates the runtime changes from PRs 420, 424, 427, 446, 447, 466, 470, 474 and 489 with the desktop workspace, durable imports and history/storage workflows in the extracted IPC architecture. Final formatting, TypeScript checks and the production build passed. The complete unit suite passed, with isolated children retaining all 24 dictation and 10 overlay contracts; Python adapter fixtures passed 47 tests. At the time (Electron app), isolated desktop, settings-write, deletion and local-data checks passed, as did Linux unpacked resource verification and packaged launch. Complete browser verification is recorded separately in the consolidation PR.

Targeted local fixture runs passed for setup recovery, including failed speech warmup and writing inference warmup, installer recovery, worker transport, residency, settings transactions, dictation ownership, golden transcript assembly and resource verification. These runs use synthetic workers, package reports and desktop ports. They establish local failure/state contracts, not successful native R2T2 inference, real GPU memory release or actual native clipboard insertion. No model installation, download, benchmark or native inference was performed as part of these fixture checks.

The consolidated scope is the existing desktop application: capture, buffered R2T2 transcription, optional Qwen3.5 previews, explicit technical vocabulary, source imports, durable history, corrections, export and local recovery. CLI/API/server adapters, editor plugins and watched folders were removed.

Speech remains R2T2 only. The stored platform selection keys `r2t2` and `r2t2Mlx` refer to one identity; execution metadata records the adapter, actual reported precision and pinned checkpoint separately. Historical Qwen speech records remain readable without creating an active Qwen speech selection. Qwen3.5 rewriting owns a separate runtime, package environment and generated-code caches.

Setup prepares an isolated candidate without switching the durable runtime pointer. Speech setup requires completed backend warmup. Writing setup performs a bounded, fixed internal inference and discards its output before verifying warmup and activating the candidate. Cancellation suppresses old progress/results, stops setup processes and its worker, and discards only the candidate selection. Child/process-tree and GPU memory release still need native validation on each platform; termination timeouts are not physical memory evidence.

The Linux readiness probe and worker use `r2t2.R2T2ASRModel`, matching the [example at the exact installed upstream source revision](https://github.com/netease-youdao/Confucius4-R2T2/blob/80c22e6140bcb9166fb9906798894fc8b18c8309/example.py). They do not import the earlier `qwen_asr` API. Speech downloads continue through immutable-revision/hash verification, with byte counters emitted by the actual verified transfer loop. Reused/resumed bytes can contribute to the current file's completion counter; this is not a measure of newly transferred network bytes or aggregate installation progress.

## Remaining native evidence (#94, #96, #97, #98, #101, #104)

Native evidence is still required for accuracy, latency, buffering under sustained capture, cancellation/process cleanup, CUDA/Metal memory release, checkpoint conversion and cold/offline setup. Buffered transcription is the supported desktop workflow. Actual Apple Silicon MLX and Windows/Linux CUDA inference, offline cached setup, installed-package replacement, decoder coverage, destination focus/clipboard delivery and physical memory release still require native evidence. Synthetic fixtures and local resource checks do not close those gates.
