# Capture stress verification

Run `bunx playwright test capture-stress.pw.ts` to exercise 100 completed captures through **one** production `PcmRecorder`, without resetting the recorder or reloading the page between sessions. The test uses Chromium's synthetic microphone, real `MediaStream` tracks, native audio contexts and worklet nodes. Its JSON report is attached to the Playwright result as `capture-stress-report`.

Each session admits 17–21 real 128-sample microphone quanta at 16 kHz. A same-origin fixture wraps the production worklet's registration and gates input after that limit; its buffering, packet emission and final flush remain the production implementation. The varying lengths leave a 128–640-sample final partial packet after a full 2048-sample packet. The test compares **every** delivered PCM16 sample with the native worklet's observed Float32 packets, including the tail, and checks the WAV length, sample rate, channel count and bit depth.

All 100 sessions must start and submit exactly once, with one stream, context and worklet each. Every tenth session queues duplicate Start and Stop commands concurrently and must still produce those same counts. Before submission, after Stop and before the next Start, all acquired tracks must be ended, all contexts closed, all source/worklet/gain nodes disconnected and recorder port handlers removed. Assertions run before emergency cleanup; the test's `finally` block releases native resources even when an assertion fails. Per-session packet observations belong to their own worklet node, so late messages cannot be attributed to a subsequent session. The harness releases retained PCM/WAV payloads after checking each capture.

The worklet readiness deadline is five seconds per session and the complete test deadline is 150 seconds. Failure messages identify the first failing session; fixture files are removed after the test. The regular `capture.pw.ts` tests also exercise the unmodified production worklet at Chromium's natural sample rate and repeated cancellation, alongside the exact single-session flush oracle.

This establishes a bounded browser capture stress check with mocked desktop bridge destinations. It does not establish physical microphone/device hotplug behavior, native MLX/CUDA inference, system clipboard/paste delivery, long-recording memory bounds, or Cancel/Stop races across UI, tray and shortcuts. Those require their own checks; this test never accesses a personal microphone, runtime or transcript history.

During implementation, three temporary production mutations were each rejected in the first session: omitting final flush delivered only 2048 of 2176 samples; omitting track stopping left resources live at submission; corrupting the last PCM16 sample failed the exact payload oracle. All mutations were restored before the final verification run.

## Capture command ownership and races

The desktop service creates a unique session ID for each accepted Start. UI, tray and shortcut controls share this service, so duplicate Starts do not acquire another identity. Start/Stop/Cancel commands and recorder started/failed/audio callbacks carry that ID through the sandboxed preload. Stop commits audio only for the current stopping session and consumes its ID before processing, so duplicate or abandoned submissions cannot create another transcript or delivery. Cancel consumes the ID immediately. A retained failed recording remains available through the explicit Retry path.

The recorder invalidates its capture generation synchronously when Cancel arrives, including while permission, worklet setup, final flush or disposal is pending. Stop checks that generation before submitting audio. Resources are released before submission. Once the submission call transfers ownership to desktop processing, a later Start can reserve its new identity even while the earlier IPC reply is pending. Old tagged commands and old cleanup cannot clear that new reservation.

Run `bunx playwright test capture-races.pw.ts` for six bounded cases using the production recorder, Chromium's synthetic microphone and unmodified native worklet: Cancel during a held final flush; new Start during a held submission reply; duplicate Start/Stop; Cancel during held permission followed by a queued new Start; stale Stop/Cancel after a newer session starts; and duplicate old Cancel while a new Start is queued behind abandoned permission. The harness controls only asynchronous boundary timing and bridge destinations, and checks capture/submission counts, session IDs and released native resources. Before the fix, the held-flush Cancel case submitted audio incorrectly. A separate reservation regression rejected the first implementation: duplicate old Cancel prevented the queued new Start from acquiring a microphone; prioritizing the newer reservation fixes that boundary.

`bun test electron/services/dictation.test.ts` exercises the public ready/Start/started/Stop path, canceled and stale callbacks, mismatched IDs, duplicate submissions during inference, exact transcript/delivery counts, cache cleanup, explicit retry and interleaved shared controls. ASR, clipboard and paste are mocked; cache files use isolated temporary directories. The default `bun run test:desktop` also sends abandoned callbacks through the real Electron preload/main IPC and verifies unchanged idle status and empty history. Optional native desktop smoke imports its prepared audio fixture through `runLab`, because a file import has no live microphone capture identity.

These checks do not establish physical microphone behavior, OS hotkey registration, native tray input, system paste, or MLX/CUDA inference. Those retain their separate hardware/manual evidence requirements.
