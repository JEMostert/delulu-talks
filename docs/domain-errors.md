# Operation failures

`src/domainErrors.ts` defines the shared `DomainError` and its serializable `DomainFailure` contract. Failures include a stable code, operation ID, operation name, user-facing message, retry policy and cancellation effect. Retry is derived from the code; callers do not infer it from backend prose. No failure automatically replays an operation or retries a paste, rewrite, recording or installation.

Worker request UUIDs are their operation IDs. Invalid requests fail before spawning, busy requests wait for an explicit retry after idle, worker exits/timeouts require reloading, unavailable/protocol failures require runtime repair, and backend failures require a manual decision. Runtime setup timeouts/failures require Repair. Unclassified application failures remain `OPERATION_FAILED` with manual retry, preserving their existing display message.

An operation timeout stops its worker generation. The timed-out request receives `TIMEOUT`, while other requests in that generation receive `OPERATION_INTERRUPTED`, each retaining its own operation ID. An explicit worker stop marks pending work `CANCELLED`. `WorkerClient.request` optionally accepts an `AbortSignal`: a pre-aborted signal cancels without starting the worker; an abort during execution stops the worker, cancels that request and interrupts siblings. Timers/listeners are removed on completion or termination. Cancellation does not report an ASR engine failure. This is process termination, not cooperative GPU cancellation or rollback of previously completed effects.

Main IPC handlers return a dedicated `delulu-operation-v1` envelope. Preload unwraps successful values, retaining all existing API return shapes and subscription disposers. It transports safe failure metadata in an Error message because Electron contextBridge discards custom Error fields. `src/bridge.ts` restores the typed Error before application consumers receive a rejection. Raw `window.delulu` callers receive the readable message plus its safe transport suffix; application code should use `bridge`. Ordinary transport errors remain ordinary errors.

Actual backend causes remain attached to the owning process's `Error.cause` and the existing local runtime diagnostic logs. Serialized causes include only an error category and bounded symbolic code, never backend messages, stacks, transcript/request contents or worker stderr. Worker and installer failures use display messages separate from their backend causes. ASR status events include the safe `failure` contract and clear stale failure metadata when a subsequent operation leaves the error phase. IPC wrapping preserves the original worker/setup operation ID rather than replacing it with the outer IPC invocation ID.
