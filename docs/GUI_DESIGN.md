# Ocean controller

The main window is an icon-only dictation controller over a procedural ocean. It opens at 800 × 620 and supports 480 × 420. The idle surface contains Copy, Record and Settings. Recording adds pause/resume and cancel; the microphone becomes Stop. Accessible names, keyboard focus and a screen-reader status describe each action without visible dashboard prose.

## Visual system

The reference is [Ocean Controller](design-concepts/04-ocean-controller.png). The shipped background is generated by `OceanBackground.tsx`, not an image: perspective caustics, slow currents, underwater light shafts and drifting motes. Pointer movement subtly shifts the scene; touches leave light rings and microphone energy drives submerged pulses. Glass controls have restrained hover, press, recording and completion feedback. Light mode changes working surfaces to arctic white while retaining the ocean.

`src/styles/shell.css` owns the shell, glass controller and sheets; `src/styles/ocean.css` owns ocean motion. Existing semantic controls use `src/styles/primitives.css`. Coral distinguishes active capture from idle cyan. Reduced-motion preferences stop continuous motion. Software compositing leaves the layered CSS ocean static.

## Layout

- Settings opens a compact sheet with microphone, language, shortcut, automatic paste and speech residency. Appearance remains in the quick sheet. One bottom dock combines recording with Home, History, Audio files, Models, Editor and Settings navigation.
- Secondary workspaces open in a larger sheet. Their content starts immediately below the compact header; workspace navigation lives in the bottom dock. The controller remains accessible below it. Escape closes the sheet; Back returns to quick settings. Visited workspaces preserve drafts using React Activity, while hidden effects are suspended.
- First-run setup opens Models when the speech engine is missing. Speech and optional Rewriting have separate tabs, install/load/repair actions, progress, cancellation and recoverable errors. Technical snapshots, disk estimates and diagnostics live under Details. Provenance and logs expand on demand.
- History starts with search and transcripts. Filters open on demand; selection reveals batch actions. History retains transcript review, edits, corrections, exports and rewrite preview/apply/undo. Audio files starts with its drop area and queue. Editor starts with its text buffer and icon toolbar; insertion previews and advanced editing tools expand on demand. Setting labels have optional info disclosures. Backups and retention live under Local data. Profile creation and rules appear before transfer and usage tools. Advanced preferences remain available without occupying the idle screen.
- Actionable errors and recovery controls may display text. Ordinary idle operation has no visible headings, status paragraphs or navigation sidebar.

## Performance

The ocean is a React component of layered gradients (light shafts, dappled light, currents, motes) moved by Tailwind animations that change only transform and opacity. Chromium selects hardware compositing on Wayland as on other desktops. The main process reports its actual compositing feature status through the preload bridge, including later GPU status changes. Until acceleration is confirmed, and whenever software compositing is active, the ocean stays static and backdrop filters are disabled. `DELULU_SOFTWARE_RENDERING=1` explicitly disables hardware acceleration for incompatible drivers; it does not affect Python speech inference.

All decorative ocean motion pauses while any workspace or quick settings sheet is open, when the window is hidden, and with reduced motion. The voice glow does not update behind a sheet or in software mode. Audio visualization subscribes locally rather than updating the entire application.

Secondary pages load on demand. Optional service discovery does not block core startup, and runtime inventory is requested only when Details is opened. Broad full-window backdrop filters are avoided; the small controller and quick sheet retain glass effects.

## Verification boundaries

Visual inspection covers the controller, sheets and compact layout. Type checking and the production build validate integration. Browser preview uses sample services and does not establish native installation, model inference or delivery to another application. Those require a configured desktop runtime.
