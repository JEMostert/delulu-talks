# Ocean controller

The main window is an icon-only dictation controller over a procedural ocean. It opens at 800 × 620 and supports 480 × 420. The idle surface contains Copy, Record and Settings. Recording adds pause/resume and cancel; the microphone becomes Stop. Accessible names, keyboard focus and a screen-reader status describe each action without visible dashboard prose.

## Visual system

The background is generated by `OceanBackground.tsx`, not an image: perspective caustics, slow currents, underwater light shafts and drifting motes. Pointer movement subtly shifts the scene; touches leave light rings and microphone energy drives submerged pulses. Glass controls have restrained hover, press, recording and completion feedback. Light mode changes working surfaces to arctic white while retaining the ocean.

`src/styles/shell.css` owns the shell, glass controller and sheets; `src/styles/ocean.css` owns ocean motion. Existing semantic controls use `src/styles/primitives.css`. Coral distinguishes active capture from idle cyan. Reduced-motion preferences stop continuous motion. Software compositing leaves the layered CSS ocean static.

## Layout

- A labeled dock is always visible around the pearl: History and Words on the left, Voice and Settings on the right. Home is the ocean with no sheet open; choosing the open page again, the close button or Escape returns there. While recording on Home the dock shows only pause, stop and cancel.
- Secondary workspaces open in a larger sheet. Their content starts immediately below the compact header; workspace navigation lives in the bottom dock. The controller remains accessible below it. Escape closes the sheet; Back returns to quick settings. Visited workspaces preserve drafts using React Activity, while hidden effects are suspended.
- First-run setup opens Settings → Dictation when the speech engine is missing. Each feature owns its setup: the speech model sits at the top of Dictation and the rewrite model inside the Rewrite card, next to the switches that use them, with progress, cancellation and recoverable errors. Models load on demand; loading, unloading, repair, runtimes, caches and diagnostics live in Settings → Advanced. Provenance and logs expand under Details.
- History starts with search, quick filters and transcripts; selection reveals batch actions. It retains transcript review, edits, corrections, exports and rewrite preview/apply/undo, and transcribes audio or video files (import button or drop) with one list of unfinished files. Words lists word packs, your own words and text shortcuts. Voice holds Siren, the agent connection and Sonar, in the order they depend on each other; Sonar names what it still needs. Settings sections follow features: Dictation, Rewrite, Output, App, Privacy, Advanced. Rows are a label and a control, with a short line only where the control would be unclear.
- Actionable errors and recovery controls may display text. Ordinary idle operation has no visible headings, status paragraphs or navigation sidebar.

## Performance

The ocean is a React component of layered gradients (light shafts, dappled light, currents, motes) moved by Tailwind animations that change only transform and opacity. The webview (WebKitGTK on Linux, WKWebView on macOS) composites with the GPU by default. The renderer asks the backend for the rendering mode (`runtime:renderingMode`) and starts with inexpensive drawing until it answers; in software mode the ocean stays static and backdrop filters are disabled. On Linux, `DELULU_SOFTWARE_RENDERING=1` turns off WebKitGTK compositing and the DMA-BUF renderer for incompatible drivers and reports software mode; it does not affect Python speech inference. The backend does not detect a driver falling back to software compositing on its own.

All decorative ocean motion pauses while any workspace or quick settings sheet is open, when the window is hidden, and with reduced motion. The voice glow does not update behind a sheet or in software mode. Audio visualization subscribes locally rather than updating the entire application.

Secondary pages load on demand. Optional service discovery does not block core startup, and runtime inventory is requested only when Details is opened. Broad full-window backdrop filters are avoided; the small controller and quick sheet retain glass effects.

## Verification boundaries

Visual inspection covers the controller, sheets and compact layout. Type checking and the production build validate integration. Browser preview uses sample services and does not establish native installation, model inference or delivery to another application. Those require a configured desktop runtime.
