# Diagnostic privacy boundaries

Source inspection for DAT-08 found three concrete exposures: worker exception responses could echo text or audio filenames; Python tracebacks included source lines and absolute paths; last-error files persisted raw backend stderr. The health-check Copy diagnostics action also exported the user-data path and the entire installed-distribution inventory.

The worker now reports fixed categories and recovery actions (memory, dependency, permission, missing file, accelerator, input, protocol, timeout, download, cancellation and unloaded model). Unknown exception prose is omitted. Python no longer prints exception tracebacks or raw exception messages. Electron classifies worker responses, abnormal exits and malformed protocol errors rather than forwarding arbitrary backend strings. This is a lossy output boundary, not a promise that regex replacement can recognize every sensitive string. Backend cause matching chooses a fixed message; it never copies matching text into output.

New last-error files contain a versioned summary with runtime role, timestamp, category, fixed action and captured diagnostic byte count. Raw stderr and exception messages are excluded. The no-history policy from DAT-06 (#237) independently suppresses automatic log writes; when those changes are integrated, its setting check must continue to wrap these safe summaries. No review or merge was performed for that integration.

Copy diagnostics constructs an explicit schema containing platform, architecture, memory, Python version, runtime availability and selected package versions. It excludes paths, backend output, transcript/history records, runtime settings and arbitrary distribution metadata. No report is sent anywhere automatically. The user-data path remains available in the locally expanded Technical details for repair; users may still deliberately copy it or photograph it.

Older last-error files and runtime inventories are preserved. They may contain raw messages, usernames or paths and should be inspected before sharing. This change does not delete, rewrite or certify their contents. Raw third-party worker stderr still has a bounded in-memory tail used for error categorization; it is not included in the new persistent summary. Setup progress and local repair controls remain visible and can include actionable filesystem locations. Dependency libraries and operating-system crash reports are outside this export boundary.

Screenshot source inspection found browser failure screenshots/traces in `playwright.config.ts`, fixture page screenshots in the browser suite, and an explicitly requested screenshot path in the Mac package harness. No application screenshot upload was found in this focused inventory. Screenshot/trace artifacts can capture whatever is visible, including local repair paths or user text if someone changes fixture/session inputs. This change does not sanitize pixels, external desktop captures or old test artifacts. Use synthetic text and inspect artifacts before sharing.
